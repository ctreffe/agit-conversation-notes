# DDR-0002: Content-led notes with a provisional QMD starter

Status: Accepted
Date: 2026-10-13
Supersedes: [DDR-0001](DDR-0001-thematic-notes-and-clarification.md)

## Context

The maintainer found the generic QMD too much like formal minutes. The document
should adapt to actual conversation contents without obligatory findings
categories or a fixed hierarchy. Date/participants should still be recorded,
and useful light emphasis should remain available.

## Decision

Keep the transcript-clarification stage, contextual questions in batches of at
most ten, faithful content synthesis and compact source footnotes from DDR-0001.
Replace its fixed layout with a minimal content-led starter. Record actual
conversation date and participants in a short header; ask for missing/uncertain
facts and mark deliberately unresolved metadata without guessing.

Choose natural headings, prose and lists to fit the content. Findings, decisions,
tasks, open questions, emphasis, opening overview, final recap and tables are
optional presentation elements. Lightly highlight useful supported aspects in
context, but do not invent findings, empty categories or a rigid minutes format.
Relevant content remains in the account even without separate labels.

The generic QMD is provisional. Evaluate it after the first completed test
project; review and revise it no later than after the second using observed
maintainer feedback. No test project is completed yet.

## Rationale

The document serves content preparation and personal recall. Flexible structure
preserves that purpose; a small factual header provides orientation. Optional
emphasis retains retrieval value without making a protocol schema compulsory.
An early revision checkpoint prevents premature standardization.

## Consequences

The skill and generic QMD follow this design. Trial files, participant metadata,
corrections and feedback stay unversioned and off GitHub under
[PDR-0002](PDR-0002-unversioned-conversation-storage.md). External storage is the
persistent default; ignored local repository placement is allowed. Only generic template changes
and conversation-free lessons enter project records. No scheduled automation or
external writes are authorized by the review checkpoint.

## Alternatives considered

- Retain mandatory topic/category/recap blocks: too rigid for the intended content-preparation use.
- Remove all highlights: discards an aspect the maintainer still finds useful.
- Freeze the template before practical tests: lacks real workflow evidence.

## Follow-up

Select exact mapped unversioned destinations/authority, run the first test and
evaluate its QMD/DOCX together. Retain the second-test revision checkpoint.
